# Content Quality Gate

## 章

`complete` にする章は次を満たします。

- 学習目標と公式 objective の対応が明記されている。
- 公式トピックごとの対応位置と根拠が Coverage Matrix に登録されている。
- 前提知識、重要用語、章のまとめ、次の学習先が明記されている。
- 専門用語は初出で日本語の説明と公式英語名を併記し、以降の表記を統一している。
- What / How / When-Why / Compare を、該当する範囲で説明している。
- 設定、パラメータ、SQL がある場合は適用条件と実行文脈が分かる。
- 重要点と混同しやすい点を区別している。
- 技術的主張が `sources.json` の公式資料で確認されている。
- 図が必要な場合はレビュー済みの図がある。
- 章末問題があり、全選択肢の理由と出典がある。

## 演習

各問題は問題文、選択肢、正解、正解理由、各誤答の理由、周辺知識、章、1つ以上のobjective、問題形式、必要選択数、解答根拠、追加学習資料を持ちます。実試験問題の記憶・再現や、正答数を稼ぐだけの不自然な distractor は使用しません。

## Coverage

1 objective の `complete` には、章、技術根拠、必要な図、章末問題、Domain 演習、模擬試験のすべてが必要です。Preview / GA など変動要素が期限切れなら `complete` を維持できません。

## レビュー

内容レビューでは最低限、技術的正確性、出典一致、試験範囲との対応、教育的な分かりやすさ、SQL と図の整合性を確認します。

### 初学者向けの文章設計

章本文は、次の基準でも点検します。

- 一つの段落には一つの論点を置き、最初の文で対象が分かるようにする。
- 新しい用語は、可能なら具体的な働きや既知概念との差を示してから名前を付ける。
- 因果関係は結果だけで終えず、なぜその結果になるのかを一文で示す。
- 複数の原因、機能、選定軸を一括りにせず、対応関係を明記する。
- 断定の範囲を公式根拠に合わせる。例外や条件がある場合は、誤解される命題を具体的に限定する。
- 具体例、図、SQL、表を置いたら、本文の概念や試験上の判断へ対応付ける。
- 同じ概念には章をまたいで同じ用語を使い、似た語への言い換えで接続しない。
- 見出しは `What` や `概要` だけで済ませず、その節で扱う対象や答える問いを特定する。
- 問いを置いた場合は本文内で答えを回収し、回収しない予告や問いを残さない。
- 章の進行を説明するだけの文や、同じ結論の言い換えを削る。

学習目標、試験範囲との対応、章のまとめ、次の学習先は、教材内を迷わず移動するために残します。
読み物としての演出より、試験範囲、判断基準、根拠を短い経路で理解できることを優先します。

この基準は、[日本語技術文書の文章規範](https://gist.github.com/k16shikano/fd287c3133457c4fd8f5601d34aa817d)と[認知リズムを生むための日本語ライティング規範](https://gist.github.com/k16shikano/eb2929f13ed19c97188393d297be8432)のうち、技術教材に適合する原則を参考にしています。
書籍的な演出、常に未解決の問いを残す構成、語り手の思考過程の再演は必須にしません。
