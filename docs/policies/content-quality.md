# Content Quality Gate

## 章

`complete` にする章は次を満たします。

- 学習目標と公式 objective の対応が明記されている。
- What / How / When-Why / Compare を、該当する範囲で説明している。
- 設定、パラメータ、SQL がある場合は適用条件と実行文脈が分かる。
- 重要点と混同しやすい点を区別している。
- 技術的主張が `sources.json` の公式資料で確認されている。
- 図が必要な場合はレビュー済みの図がある。
- 章末問題があり、全選択肢の理由と出典がある。

## 演習

各問題は問題文、選択肢、正解、正解理由、各誤答の理由、周辺知識、章、objective、解答根拠、追加学習資料を持ちます。実試験問題の記憶・再現や、正答数を稼ぐだけの不自然な distractor は使用しません。

## Coverage

1 objective の `complete` には、章、技術根拠、必要な図、章末問題、Domain 演習、模擬試験のすべてが必要です。Preview / GA など変動要素が期限切れなら `complete` を維持できません。

## レビュー

内容レビューでは最低限、技術的正確性、出典一致、試験範囲との対応、教育的な分かりやすさ、SQL と図の整合性を確認します。
