# M1-Q38 狭いfilterとJOIN増大

- Layer: mock
- Objective IDs: 4.1
- Question type: multiple-select
- Required selections: 2
- Chapter: textbook/domain-4/01-evaluate-query-performance.md
- Status: review

## 問題

1日分の売上検索がほぼ全partitionをscanし、JOIN後の行数も要件上の予想より大幅に増えている。まず確認すべきものを2つ選べ。

2つ選んでください。

## 選択肢

- A. queued_provisioning_timeだけでJOIN増大の原因を判断する
- B. 日付filterとpartitionの値域・data配置
- C. JOIN条件と結合keyの重複・対応行数
- D. warehouseのsizeとAUTO_SUSPENDだけで両方の症状を診断する

## 正解

B, C

## 正解理由

B: 狭い要件で広くscanする原因を調べる。

C: 意図しないmany-to-manyや条件漏れを確認する。

## 各誤答が誤りである理由

- A: 誤り。compute準備の待機時間ではJOIN条件やkeyの対応行数は分からない。
- B: 正しい。狭い要件で広くscanする原因を調べる。
- C: 正しい。意図しないmany-to-manyや条件漏れを確認する。
- D: 誤り。sizeや停止設定だけではfilterの値域やJOIN条件の問題を特定できない。
