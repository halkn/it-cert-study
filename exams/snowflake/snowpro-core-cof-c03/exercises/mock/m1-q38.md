# M1-Q38 狭いfilterとJOIN増大

- Layer: mock
- Objective IDs: 4.1
- Question type: multiple-select
- Required selections: 2
- Chapter: textbook/domain-4/01-evaluate-query-performance.md
- Status: complete

## 問題

1日分の売上検索がほぼ全partitionをscanし、JOIN後の行数も要件上の予想より大幅に増えている。まず確認すべきものを2つ選べ。

2つ選んでください。

## 選択肢

- A. Profileのlocal／remote spill量を比較し、中間データのメモリー不足を調べる
- B. 日付filterとpartitionの値域・data配置
- C. JOIN条件と結合keyの重複・対応行数
- D. queued_overload_timeとwarehouseの同時実行数を比較し、混雑による待機を調べる

## 正解

B, C

## 正解理由

B: 狭い要件で広くscanする原因を調べる。

C: 意図しないmany-to-manyや条件漏れを確認する。

## 各誤答が誤りである理由

- A: 誤り。spillはメモリー不足を調べる指標ですが、設問で観測された広いscan範囲とJOINの行数増大の原因を直接説明しません。まずfilterと結合条件を調べ、処理対象の増加がspillにつながっていないかはその後に確認します。
- B: 正しい。狭い要件で広くscanする原因を調べる。
- C: 正しい。意図しないmany-to-manyや条件漏れを確認する。
- D: 誤り。負荷によるqueueは実行開始前の待機を調べる指標です。実行中のscan範囲やJOINによる行数増大を診断する指標とは異なります。
