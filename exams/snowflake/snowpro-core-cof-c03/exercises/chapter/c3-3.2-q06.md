# C3-3.2-Q06 Stream offsetの進み方

## 問題
Streamのoffsetが進むのはどの操作を行ったときですか。
## 選択肢
- A. streamを`SELECT`したとき
- B. 明示的なtransaction内でstreamを`SELECT`したとき
- C. `SHOW STREAMS`を実行したとき
- D. streamをDML文で使ってデータを書き込んだとき

## 正解

D

## 正解理由
offsetはstreamをDML transactionで使ったときに進みます。`INSERT ... SELECT FROM stream`や`CREATE TABLE AS SELECT`がこれにあたります。
## 各誤答が誤りである理由
- A: `SELECT`だけではoffsetは進みません。同じ変更が何度でも返ります。
- B: 明示的なtransaction内であっても、`SELECT`だけならoffsetは進みません。
- C: `SHOW STREAMS`はobjectの一覧を返すcommandで、消費とは無関係です。
- D: DML transactionでstreamを使うとoffsetが進み、次回以降はその後の変更だけが返ります。

## 周辺知識
消費するtaskとセットで運用しないと、offsetが古いままdata retentionの外へ出てstaleになります。`SYSTEM$STREAM_HAS_DATA`で未消費の変更の有無を判定できます。
