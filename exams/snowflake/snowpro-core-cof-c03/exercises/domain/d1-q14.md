# D1-Q14 Pruningとclusteringの判断

- Layer: domain
- Objective IDs: 1.5
- Question type: multiple-select
- Required selections: 2
- Chapter: `textbook/domain-1/05-storage-concepts.md`
- Status: complete

## 問題

数TBの注文tableで、日付範囲を絞るqueryが頻繁に実行されます。多くのmicro-partitionの値範囲が重なり、Query Profileでは対象partitionの大半をscanしています。配置と検索条件の関係を改善する判断として適切なものを2つ選んでください。

## 選択肢

- A. warehouseのcluster数を増やせば、日付の値範囲の重なり自体が解消される
- B. 日付filterとmicro-partitionの値範囲metadataを照合して、pruningが弱い理由を確認する
- C. 日付expressionのclustering keyを候補にし、scan削減効果とreclustering・履歴storage費用を比較する
- D. ORDER BYを付けた通常viewを作れば、base tableのmicro-partition配置が書き換わる

## 正解

B, C

## 正解理由

値範囲metadataとpredicateの関係からscan候補が決まるため、重なりとpruningを確認できます。 大規模tableの反復selective filterでは配置改善を評価できますが、維持費との比較も必要です。

## 各誤答が誤りである理由

- A: Cluster数は同時実行のcompute容量であり、base tableの保存配置を変更しません。
- B: 値範囲metadataとpredicateの関係からscan候補が決まるため、重なりとpruningを確認できます。
- C: 大規模tableの反復selective filterでは配置改善を評価できますが、維持費との比較も必要です。
- D: 通常viewはquery定義を保存し、ORDER BYは返却順序を扱います。base tableの保存配置は書き換えません。

## 周辺知識

Micro-partitionはSnowflakeが自動管理します。Clustering keyの有無だけで速さを決めず、現在の自然な配置、変更量、query頻度を確認します。
