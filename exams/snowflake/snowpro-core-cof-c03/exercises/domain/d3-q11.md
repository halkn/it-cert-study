# D3-Q11 Git認証とstorage integration

- Layer: domain

## 問題

認証を要求しない公開Git repositoryのSQLをSnowflakeへ同期し、別途S3のファイルをexternal stageで利用したい要件があります。構成として正しいものを2つ選んでください。

## 選択肢

- A. 公開Git repositoryでも、常にusernameとtokenを持つsecretを作りGIT_CREDENTIALSへ指定する
- B. Git repository objectのORIGINへS3 bucket URLを指定し、storage integrationをGitのAPI_INTEGRATIONに指定する
- C. 公開Gitにはgit_https_apiのAPI integrationとGit repository objectを使い、認証なしならsecretを省略する
- D. S3にはstorage integrationとexternal stageを使い、Git用API integrationとは分ける

## 正解

C, D

## 正解理由

Git用API integrationは許可URLを定め、repository objectがremoteのcloneを保持します。認証なしではsecret不要です。 Storage integrationはcloud storageへのアクセスを集約し、external stageがファイル場所を指定します。

## 各誤答が誤りである理由

- A: 認証なしのGit serverではsecretとGIT_CREDENTIALSを省略できます。token認証の条件を一般化しています。
- B: GitのORIGINはHTTPS repository URLで、API_INTEGRATIONにはGit用API integrationを指定します。
- C: Git用API integrationは許可URLを定め、repository objectがremoteのcloneを保持します。認証なしではsecret不要です。
- D: Storage integrationはcloud storageへのアクセスを集約し、external stageがファイル場所を指定します。

## 周辺知識

Token認証ならsecretを追加します。ALTER GIT REPOSITORY ... FETCHはremoteからcloneへの同期で、branch／tag／commitのpathから参照します。
