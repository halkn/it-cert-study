# D1-Q15 IDE・自動化・処理APIの組合せ

- Layer: domain
- Objective IDs: 1.2, 1.6
- Question type: multiple-select
- Required selections: 3
- Chapter: `textbook/domain-1/02-interfaces-and-tools.md`
- Status: complete

## 問題

開発者はVS CodeでSnowpark Python stored procedureをdebugし、承認したSQLとapplication projectをCIから反復deployしたいと考えています。大量dataの変換は全件をlocalへfetchせずSnowflake側で行います。この構成を支える選択を3つ選んでください。

## 選択肢

- A. Snowflake CLIをCIのSQL・project操作に使う
- B. Snowsightのchart設定をCI deployment手順として使う
- C. VS CodeのSnowflake拡張をIDEでの接続・authoring・debugに使う
- D. Python Connectorで全件fetchした後、local Pythonだけで変換する
- E. SnowparkのDataFrame APIで変換を記述し、Snowflake側で処理する

## 正解

A, C, E

## 正解理由

CLIはfileとcommandによる反復・自動化に適し、SQLとdeveloper workloadを扱えます。 公式VS Code拡張はSQLとSnowpark開発を既存IDEへ統合できます。 Snowparkはlanguage APIからlogical planを構築し、Snowflake側でdata処理します。

## 各誤答が誤りである理由

- A: CLIはfileとcommandによる反復・自動化に適し、SQLとdeveloper workloadを扱えます。
- B: Chartはquery結果の可視化であり、承認済みprojectをCIからdeployする手順ではありません。
- C: 公式VS Code拡張はSQLとSnowpark開発を既存IDEへ統合できます。
- D: 全件fetch後のlocal変換は、dataを移動せずSnowflake側で処理する要件に反します。
- E: Snowparkはlanguage APIからlogical planを構築し、Snowflake側でdata処理します。

## 周辺知識

Interface、deploy tool、処理APIは異なる役割です。どのtoolでも接続先、role、warehouse等のcontextと権限を確認します。
