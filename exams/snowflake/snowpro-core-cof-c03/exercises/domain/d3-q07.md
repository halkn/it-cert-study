# D3-Q07 Dynamic Tableとstream + taskの選定
- Layer: domain
- Objective IDs: 3.2
- Question type: single-choice
- Required selections: 1
- Chapter: `textbook/domain-3/02-automated-ingestion.md`
- Status: complete
## 問題
複数tableをjoinして集約した結果を、常に15分以内の鮮度で維持したい要件があります。処理内容はSQLだけで表現でき、独自ロジックは不要です。最も適した構成はどれですか。
## 選択肢
- A. `TARGET_LAG = '15 minutes'`のdynamic tableを定義する
- B. 各tableにstreamを作り、15分間隔のtaskでmergeする
- C. 15分間隔でtarget tableへ`CREATE OR REPLACE TABLE AS SELECT`するtaskを作る
- D. Snowpipeで15分ごとにファイルを再ロードする

## 正解

A

## 正解理由
SQLで表現できる結果を一定の鮮度で保つ要件は、dynamic tableのtarget lagで宣言的に満たせます。依存関係の追跡とrefreshの順序はSnowflakeが扱います。
## 各誤答が誤りである理由
- A: target lagを宣言すれば、依存関係の追跡とrefreshの実行をSnowflakeへ委ねられます。
- B: stream + taskでも実現できますが、依存順序と再実行を自分で設計する必要があり、この要件では過剰です。
- C: 毎回全体を作り直すため、増分で済む場合に無駄が大きくなります。
- D: Snowpipeはファイル到着を起点とするロード機能で、既存tableの集約結果を維持する機能ではありません。

## 周辺知識
手続き的な処理や外部呼び出しが必要な場合はstream + taskを選びます。dynamic tableのdefinitionではstored procedureと外部関数を使えません。
